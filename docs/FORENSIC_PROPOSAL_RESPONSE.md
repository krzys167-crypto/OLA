# OLA di-OS — Response to Forensic Proposal

## Position

The proposal is accepted as a source of testable hypotheses and collection requirements. Its conclusions are not accepted automatically. Every material claim must be backed by an artifact that an evaluator outside the producing runtime can independently inspect.

## Claim-to-proof matrix

| Claim | Required proof | State until proof exists |
|---|---|---|
| Source is the exact code that ran | actual checkout SHA + manifest/source SHA equality | BLOCKED on mismatch |
| Runtime is generated by the claimed six-agent flow | 6 real execution records + provider trace + run_id | UNKNOWN / BLOCKED |
| LLM responses are genuine | provider-side identity or independent provider trust anchor | REVIEW_REQUIRED from local trace only |
| Runtime evidence was not altered | per-file SHA-256 + archive hash + hash-chain verification | VERIFIED only after recomputation |
| Verifier is independent | separate verifier component + independent source binding checks | REVIEW_REQUIRED if merely self-declared |
| Human approval is real | separate approver event/record | REVIEW_REQUIRED / BLOCKED |
| Freeze is externally anchored | independently verifiable attestation/transparency-log record | REVIEW_REQUIRED until verified |
| Workstation run really occurred on ZBook | physical host registration + real runtime evidence + external artifact | UNKNOWN until ZIP is independently reviewed |
| Cost/use is real | raw Usage and Costs API export + manifest + hashes | UNKNOWN until exported |

## Anti-self-certification rules

1. A manifest cannot establish its own authenticity.
2. A caller-supplied SOURCE_SHA cannot by itself prove that the payload was created from that source.
3. A local response digest establishes captured-content integrity, not provider authenticity.
4. CI PASS is not production VERIFIED when the production source signature is absent.
5. A skipped optional job must be visible as SKIPPED, never translated to VERIFIED.
6. REVIEW_REQUIRED is a terminal intermediate state, not an alias for PASS.

## Current OLA corrections

- Canonical `SOURCE_SHA` was introduced for PR and post-merge execution.
- Runtime records now carry `source_commit` and timing evidence.
- Igor checks the complete typed agent evidence set rather than mixing `provenance.runtime` and `decision.candidate` records.
- Ollama CodeAct uses structured JSON mode and bounded generation; a malformed or contradictory model proposal blocks execution.
- Provider response identity is represented as `response_id` when provider-issued or `response_digest` when no provider ID is supplied.
- Docker image content ID and Ollama model digest are collected by the workstation script.
- Tamper verification mutates actual evidence payload and expects rejection.
- A standalone forensic gate now exposes `VERIFIED`, `REVIEW_REQUIRED`, `UNKNOWN`, and `BLOCKED` states.

## Production closure

The production closure condition is:

`SOURCE -> RUNTIME -> ARTIFACT -> HASH -> INDEPENDENT VERIFY -> SIGNED SOURCE -> EXTERNAL FREEZE`

Every edge is required. A missing edge blocks production closure.

## Current observed blockers

- Current main remains the production baseline; forensic closure changes are not merged.
- Exact forensic snapshot source-signature verification is still not proven.
- Physical ZBook runtime artifact has not yet been independently reviewed.
- Real OpenAI organization usage/cost export has not yet been captured.
- Provider authenticity for a local Ollama endpoint remains REVIEW_REQUIRED without an external provider trust anchor.
- Latest forensic CI must complete successfully on the latest branch HEAD before the branch can be considered implementation-verified.

## Response format

When reporting the forensic proposal to a reviewer, use:

`CLAIM → EVIDENCE → INDEPENDENT CHECK → STATUS → REMAINING GAP`

Never report only the claim or the producing system's own status.
